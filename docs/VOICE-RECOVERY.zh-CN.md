# 1.2.4 语音稳定性修复

[English](VOICE-RECOVERY.md) · [安装指南](INSTALL.zh-CN.md)

本版针对微信输入法使用反馈中的开头漏字、打开系统声音设置后无输入电平，以及短按录音无法结束，修复了应用内部的音频和录音状态处理。没有新增菜单操作。

- 按下语音键后先缓存音频。判定短按或长按并发出输入法快捷键后，等待 400 ms 再送出缓存。短按松开后的重新开麦继续使用同一份缓存，避免丢弃开头。输入法启动速度因电脑而异，这个等待时间不代表已经确认输入法准备完毕。
- 结束录音时先发送缓存的尾部再结束输入法录音。音频无法继续输出时，最多等待 2 秒，随后仍释放快捷键。
- 音频引擎监听配置变化，在独立队列上重新绑定 BlackHole 并重建输出。每 500 ms 检查停转、输出设备变化及有音频积压但没有渲染回调的状态，失败后限速重试。恢复过程中保留音频缓存。
- 开麦和长按判定任务带有会话标识，可在停止或异常时取消。连续 3 秒没有音频数据会关闭麦克风并复位快捷键；判断依据是数据到达，不是说话音量。新的按键流能从漏掉上次松键的状态中恢复。
- 短按结束时立即要求遥控器关麦，不再依赖松键通知。若 2 秒内没有停止确认，即使音频仍在到达，也会复位本地录音状态并重发关闭命令；等待关闭期间停止保活。
- 保活使用调度定时器；蓝牙断开、写入失败、遥控器超时和正常退出统一清理录音状态。按键映射与系统声音设置入口保持原样。

## 验证情况

自动测试覆盖缓存开头、保留尾部、连续短按、开麦竞争、取消过期任务、异常停止、静音数据保活、漏掉松键后恢复，以及解码同步状态隔离。独立 BlackHole 测试通过了配置变化通知后的重建、无通知停转后的自动恢复。

这些验证使用自动化事件和合成数据，没有在用户连接遥控器的另一台 Mac 上录制或验证微信输入法。本版提供相应修复，实际改善情况仍需在目标电脑复测。

## 升级后复测

1. 退出旧版，用新版替换 `~/Applications/RemoteBuddy.app`，重新打开。已有依赖和配置无需重装。
2. 确认微信输入法使用 **BlackHole 2ch**。分别测试短按和按住说话，并测试说完后立即松键。
3. 打开系统声音设置、查看输入电平，关闭面板后继续录音。
4. 连续进行多次短按开始、短按结束，检查是否都能退出录音状态。

如果仍有问题，在复现后导出最近十分钟的数值诊断日志：

```sh
/usr/bin/log show --last 10m --style compact --info --predicate 'subsystem == "local.codex.RemoteMic" AND category == "audio"' > "$HOME/Desktop/RemoteBuddy-voice-diagnostics.txt"
```

日志包括源采样率、首包等待、包间隔、缓存与补零数量、音频恢复次数和超时事件，不保存语音内容。
